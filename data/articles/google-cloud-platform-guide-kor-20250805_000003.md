# The Data Scientist's Guide to Google Cloud Platform: From Big Data to Deployed AI

## 소개: GCP가 데이터 과학 및 AI를 위한 최고의 클라우드인 이유

수많은 클라우드 컴퓨팅 플랫폼 속에서 각 주요 플랫폼은 저마다의 고유한 DNA를 가지고 있습니다. 어떤 플랫폼은 전자상거래 물류에서, 또 다른 플랫폼은 엔터프라이즈 소프트웨어에서 시작되었지만, Google Cloud Platform(GCP)은 데이터를 다루는 치열한 과정 속에서 만들어졌습니다. 구글은 처음부터 데이터 회사였으며, 이전에는 상상할 수 없었던 규모의 문제들을 해결해 왔습니다. 이러한 유산은 GCP의 기반이 되어, 데이터 과학자, 머신러닝 엔지니어, AI 혁신가들에게 독보적으로 강력한 생태계를 제공합니다. GCP는 단순히 인프라를 제공하는 플랫폼이 아니라, 가장 복잡한 데이터 문제에 대해 정교하게 관리되는 솔루션을 제공합니다.

### 인프라를 넘어: GCP의 데이터 우선 철학

많은 클라우드 플랫폼은 가상 머신과 스토리지를 대여하는 서비스형 인프라(IaaS)에 중점을 두고 시작했습니다. GCP 역시 세계적 수준의 인프라를 제공하지만, 데이터 우선 철학을 바탕으로 구축되었습니다. GCP의 많은 대표 서비스들은 단순히 고객에게 제공되는 제품이 아니라, 검색, YouTube, Gmail과 같은 구글의 핵심 서비스를 구동하는, 전 세계적인 규모에서 검증된 바로 그 기술들입니다.

고성능 NoSQL 데이터베이스인 **Cloud Bigtable**이나 세계 최초의 글로벌 분산 관계형 데이터베이스인 **Cloud Spanner**와 같은 서비스들은 타의 추종을 불허하는 일관성과 낮은 지연 시간으로 막대한 운영 및 분석 워크로드를 처리하도록 설계되었습니다. 이는 여러분이 GCP를 사용할 때, 최신 데이터의 속도, 양, 다양성에 사후적으로 적응한 플랫폼이 아니라, 이를 위해 근본적인 아키텍처가 설계된 플랫폼을 활용하고 있음을 의미합니다.

### 주요 차별점: 서버리스 분석, 통합 AI, 글로벌 규모

GCP의 데이터 중심 접근 방식은 데이터 전문가들에게 특히 매력적인 몇 가지 주요 차별점으로 나타납니다.

*   **서버리스 분석:** GCP 분석 서비스의 핵심은 **BigQuery**입니다. 이는 완전 관리형 서버리스 데이터 웨어하우스로, 인프라 관리 없이 페타바이트 규모의 SQL 쿼리를 몇 초 만에 실행할 수 있게 해줍니다. 데이터 과학자들에게 진정한 게임 체인저는 **BigQuery ML**인데, 이를 통해 익숙한 SQL 구문을 사용하여 BigQuery 내에서 직접 머신러닝 모델을 구축하고 실행할 수 있습니다. 이는 머신러닝의 대중화를 이끌어 데이터 분석가들도 쉽게 접근할 수 있게 하고, 데이터에서 인사이트를 얻기까지의 과정을 극적으로 가속화합니다.

*   **통합 AI:** 머신러닝 수명주기는 데이터 준비, 학습, 튜닝, 배포, 모니터링을 위한 여러 도구들을 조각보처럼 엮어 사용해야 하므로 단편화될 수 있습니다. GCP는 전체 ML 워크플로우를 하나의 플랫폼으로 통합하는 **Vertex AI**로 이 문제를 해결합니다. AutoML을 사용한 자동 모델 구축부터 맞춤형 학습 및 MLOps에 이르기까지, Vertex AI는 AI 애플리케이션을 구축하고 확장하는 과정을 간소화합니다. 여기에 **Cloud Vision API** 및 **Cloud Natural Language API**와 같은 강력한 사전 학습된 API가 더해져, 간단한 REST 호출만으로 정교한 AI 기능을 애플리케이션에 통합할 수 있습니다.

*   **글로벌 규모 및 컨테이너화:** 모델의 가치는 배포 방식에 따라 결정됩니다. GCP는 프로덕션 AI를 위한 견고하고 확장 가능한 인프라를 제공하는 데 탁월합니다. **Google Kubernetes Engine(GKE)**은 컨테이너화된 애플리케이션을 배포하기 위한 업계 최고의 관리형 환경입니다. 데이터 과학자에게 이는 ML 모델과 종속성을 컨테이너로 패키징하여 확장, 관리, 업데이트를 자동화하는 플랫폼에 배포할 수 있음을 의미하며, 이를 통해 AI 서비스의 복원력과 고가용성을 보장할 수 있습니다.

## 파트 1: 데이터 기반 - 데이터 세트 저장 및 관리

정교한 AI 모델을 구축하기 전에 데이터에 대한 견고하고 확장 가능한 기반이 필요합니다. Google Cloud Platform(GCP)은 모든 규모와 형식의 데이터 세트를 처리하도록 설계된 포괄적인 스토리지, 데이터베이스 및 분석 서비스 제품군을 제공합니다. 데이터 레이크의 원시 비정형 파일부터 실시간 애플리케이션을 위한 고도로 구조화된 트랜잭션 데이터에 이르기까지, 올바른 솔루션을 선택하는 것은 모든 데이터 과학 프로젝트의 첫 번째 중요한 단계입니다.

### Cloud Storage: 비정형 데이터를 위한 확장 가능한 데이터 레이크

GCP 데이터 스토리지의 핵심에는 확장성이 뛰어나고 내구성이 강한 객체 스토리지 서비스인 **Cloud Storage**가 있습니다. 이를 데이터 레이크, 즉 이미지, 동영상, 오디오 파일, 로그, 텍스트 문서와 같은 모든 원시 비정형 데이터를 위한 중앙 저장소로 생각할 수 있습니다. 거의 무한한 확장성과 높은 내구성 덕분에 머신러닝 모델 학습에 필요한 방대한 양의 데이터를 수집하고 저장하기 위한 완벽한 출발점이 됩니다.

### Persistent Disk 및 Filestore: 컴퓨팅 인스턴스를 위한 스토리지

Compute Engine을 사용하여 가상 머신(VM)에서 계산을 실행할 때는 VM에 직접 연결된 스토리지가 필요합니다.
*   **Persistent Disk**는 고성능 블록 스토리지 서비스로, 본질적으로 VM의 가상 하드 드라이브 역할을 합니다. 코드를 저장하거나, 활발하게 처리 중인 소규모 데이터 세트를 저장하거나, 운영 체제의 부팅 디스크로 사용하기에 이상적입니다.
*   **Filestore**는 완전 관리형 NAS(네트워크 연결 스토리지) 솔루션을 제공합니다. 여러 VM 또는 Google Kubernetes Engine(GKE) 컨테이너가 동일한 파일 시스템에 동시에 액세스하고 공유해야 하는 시나리오를 위해 설계되었으며, 이는 분산 학습이나 공유 개발 환경에서 일반적입니다.

### 피처 스토어 및 메타데이터를 위한 관리형 데이터베이스

데이터 레이크는 원시 데이터에 적합하지만, 데이터 과학자들은 종종 피처 스토어, 실험 메타데이터 또는 애플리케이션 백엔드와 같은 구조화되고 쿼리 가능한 스토리지가 필요합니다. GCP의 관리형 데이터베이스는 서버 관리의 운영 오버헤드를 제거하여 데이터 자체에 집중할 수 있도록 합니다.

#### Cloud SQL: 관리형 관계형 데이터베이스(MySQL, PostgreSQL, SQL Server)

전통적인 관계형 데이터 요구사항을 위해 **Cloud SQL**은 완전 관리형 MySQL, PostgreSQL 및 SQL Server 인스턴스를 제공합니다. 구조화된 메타데이터(예: 모델 매개변수 및 결과 추적), 애플리케이션의 사용자 정보 또는 소규모 분석 결과를 저장하는 데 탁월한 선택입니다. 친숙하고 사용하기 쉬워 많은 표준 데이터베이스 작업에 적합합니다.

#### Cloud Spanner 및 Bigtable: 대규모 애플리케이션을 위한 글로벌 확장형 데이터베이스

애플리케이션의 데이터 요구사항이 기존 관계형 데이터베이스의 규모를 초과할 때 GCP는 두 가지 강력한 글로벌 확장형 옵션을 제공합니다.
*   **Cloud Spanner**는 관계형 데이터베이스의 강력한 일관성과 SQL 인터페이스(ACID 트랜잭션 제공)를 NoSQL 데이터베이스의 수평적 확장성과 결합한 독특한 데이터베이스입니다. 트랜잭션 무결성과 대규모 확장이 모두 필요한 미션 크리티컬한 글로벌 애플리케이션을 위해 구축되었습니다.
*   **Bigtable**은 매우 짧은 지연 시간으로 대규모 분석 및 운영 워크로드를 위해 설계된 완전 관리형 와이드 컬럼 NoSQL 데이터베이스입니다. 이는 검색 및 Gmail과 같은 핵심 Google 서비스를 구동하는 것과 동일한 기술로, 시계열 데이터, IoT 스트림 및 대규모 실시간 개인화 엔진에 이상적입니다.

### BigQuery: 분석을 위한 서버리스 데이터 웨어하우스

데이터가 저장되면 다음 단계는 이를 분석하는 것입니다. **BigQuery**는 비즈니스 민첩성을 위해 설계된 Google Cloud의 완전 관리형 서버리스 데이터 웨어하우스입니다. 이를 통해 페타바이트 규모의 데이터 세트에 대해 초고속 SQL 쿼리를 실행할 수 있습니다. 스토리지와 컴퓨팅을 분리하므로 Cloud Storage의 데이터를 직접 분석하거나 BigQuery에 로드하여 관리되고 최적화된 성능을 얻을 수 있습니다. 이는 GCP에서 대부분의 데이터 과학 작업을 위한 분석 엔진 역할을 하며, 표준 SQL 쿼리를 사용하여 BigQuery 내에서 직접 머신러닝 모델을 생성하고 실행할 수 있는 BigQuery ML과 같은 서비스의 기반이 됩니다.

## 파트 2: 데이터 분석 및 준비 - BigQuery의 힘

Google Cloud Platform에 데이터 과학자를 위한 심장이 있다면, 그것은 바로 BigQuery입니다. 단순한 데이터 웨어하우스를 넘어, BigQuery는 완전 관리형 페타바이트급 분석 엔진으로 데이터 탐색, 준비, 심지어 머신러닝의 기반 역할을 합니다. 그 아키텍처와 기능은 GCP의 데이터 중심 정체성의 핵심이며, 데이터 과학자들이 이전에는 상상할 수 없었던 규모와 속도로 작업할 수 있도록 지원합니다.

### BigQuery의 서버리스 아키텍처 이해하기
BigQuery에 대해 가장 먼저 이해해야 할 점은 *서버리스*라는 것입니다. 이는 서버가 없다는 의미가 아니라, 사용자가 서버를 관리할 필요가 없다는 뜻입니다. 프로비저닝할 클러스터도, 패치할 소프트웨어도, 확장하거나 축소할 인프라도 없습니다. Google이 이 모든 것을 배후에서 처리합니다.

이는 스토리지와 컴퓨팅을 분리하는 BigQuery의 혁신적인 아키텍처 덕분에 가능합니다. 데이터는 내구성이 뛰어난 컬럼 기반 스토리지 시스템에 저장되고, 쿼리는 Dremel이라는 대규모 병렬 실행 엔진에 의해 실행됩니다. 이러한 분리 덕분에 스토리지와 컴퓨팅 리소스를 독립적으로 확장할 수 있으며, 실행한 쿼리와 저장한 데이터에 대해서만 비용을 지불하면 됩니다. 데이터 과학자에게 이는 해방과도 같습니다. 인프라 관리가 아닌 데이터에 질문을 던지는 데 온전히 집중할 수 있기 때문입니다(Google Cloud, n.d.).

### 페타바이트 규모에서 EDA를 위한 SQL 쿼리 실행
데이터의 작은 샘플로 탐색적 데이터 분석(EDA)을 수행하던 시대는 끝났습니다. BigQuery는 테라바이트, 심지어 페타바이트에 달하는 대규모 데이터셋에 대해 표준 SQL 쿼리를 실행하고 몇 초 또는 몇 분 안에 결과를 반환하도록 설계되었습니다. 이를 통해 전체 데이터셋을 분석하여 작은 샘플에서는 놓칠 수 있는 패턴과 이상치를 발견할 수 있습니다.

요약 통계를 계산하든, 여러 대형 테이블에 걸쳐 복잡한 조인을 실행하든, 방대한 로그 파일에서 특정 이벤트를 검색하든, BigQuery의 성능은 EDA 프로세스를 혁신합니다. 대규모 데이터를 대화형으로 쿼리하고 시각화하여 더 빠른 인사이트와 더 강력한 특성 공학으로 이어질 수 있습니다.

### BigQuery ML 소개: 데이터 웨어하우스에서 직접 모델 구축하기
데이터 전문가를 위한 BigQuery의 가장 강력한 기능 중 하나는 BigQuery ML(BQML)입니다. Google의 문서에 명시된 바와 같이, BQML은 "사용자가 표준 SQL 쿼리를 사용하여 BigQuery 내에서 직접 머신러닝 모델을 생성하고 실행할 수 있게 해줍니다"(Google Cloud, n.d.).

간단한 `CREATE MODEL` 구문만으로 데이터를 이동하지 않고도 머신러닝 모델을 훈련, 평가하고 예측을 얻을 수 있습니다. 이는 머신러닝을 민주화하여 SQL에 능숙한 데이터 분석가와 과학자들이 쉽게 접근할 수 있도록 만듭니다. 다음과 같은 모델을 구축할 수 있습니다.
*   **분류:** (예: 로지스틱 회귀, 부스티드 트리) 고객 이탈 예측.
*   **회귀:** (예: 선형 회귀) 매출 예측.
*   **클러스터링:** (예: K-평균) 고객 세분화.
*   **그 외**, 시계열 예측 및 행렬 분해 등.

전체 워크플로우를 데이터 웨어하우스 내에 유지함으로써 BQML은 모델 개발을 단순화하고 데이터 이동을 줄이며 보안을 강화합니다.

### BigQuery를 노트북 및 BI 도구에 연결하기
BigQuery는 독립적으로 존재하지 않습니다. 데이터 과학자들이 매일 사용하는 도구들과 원활하게 연결되는 중앙 진실 공급원(central source of truth)으로 설계되었습니다.
*   **Vertex AI Notebooks:** Python 노트북에서 BigQuery 클라이언트 라이브러리를 사용하여 BigQuery의 데이터를 pandas DataFrame으로 가져와 복잡하고 맞춤화된 분석, Matplotlib 및 Seaborn과 같은 라이브러리를 사용한 고급 시각화, 또는 TensorFlow나 PyTorch와 같은 프레임워크에서 맞춤 모델을 훈련하는 데 사용할 수 있습니다.
*   **비즈니스 인텔리전스(BI) 도구:** BigQuery는 Looker(Google 자체 BI 도구), Tableau, Power BI와 같은 주요 BI 플랫폼을 위한 네이티브 커넥터를 제공합니다. 이를 통해 BigQuery의 실시간 데이터로 구동되는 대화형 대시보드를 구축하고 공유하여 조직 전체의 이해관계자들이 셀프서비스 분석을 수행할 수 있도록 지원합니다.

이 강력한 생태계 통합은 BigQuery를 Google Cloud에서 데이터 과학 워크플로우의 다재다능하고 필수적인 핵심으로 만듭니다.

## 파트 3: 모델 개발 및 학습 - Vertex AI 생태계

데이터가 준비되고 액세스 가능해지면 다음 단계는 모델 개발 및 학습입니다. 이를 위한 Google Cloud의 최고 환경은 전체 머신러닝(ML) 수명 주기를 관리하도록 설계된 포괄적인 플랫폼인 Vertex AI입니다. 이 플랫폼은 로우코드 솔루션을 선호하는 사람부터 심층적인 맞춤 설정이 필요한 사람까지 모든 기술 수준의 데이터 과학자를 위한 도구 모음을 제공합니다.

### Vertex AI: 전체 ML 수명 주기를 위한 통합 플랫폼

Vertex AI는 Google의 ML 제품의 초석으로서 모든 ML 도구를 단일 통합 플랫폼으로 통합합니다. 주요 목표는 ML 모델의 구축, 배포 및 확장을 단순화하고 가속화하는 것입니다. 데이터 수집 및 실험에서 모델 배포 및 모니터링에 이르는 전체 MLOps 워크플로우를 위한 통합 UI와 API를 제공함으로써 Vertex AI는 데이터 과학팀이 더 효과적으로 협업하고 프로토타입에서 프로덕션으로 더 빠르게 전환할 수 있도록 돕습니다.

### Vertex AI Workbench: 관리형 JupyterLab 노트북

대부분의 데이터 과학자에게 여정은 노트북에서 시작됩니다. Vertex AI Workbench는 완전 관리형 엔터프라이즈급 JupyterLab 환경을 제공합니다. 이 노트북은 단순한 격리된 인스턴스가 아니라 GCP 생태계와 긴밀하게 통합되어 있습니다. 이를 통해 BigQuery 및 Cloud Storage의 데이터에 원활하게 액세스하고, 버전 관리를 위해 Git 리포지토리와 쉽게 통합하며, 필요에 따라 컴퓨팅 리소스를 확장할 수 있어 탐색, 개발 및 실험을 위한 이상적인 대화형 환경이 됩니다.

### 학습 옵션: AutoML 대 맞춤 학습 작업

Vertex AI는 다양한 요구 사항과 전문 지식 수준에 맞는 유연한 학습 옵션을 제공합니다.

*   **AutoML:** 최소한의 ML 전문 지식으로 고품질 모델을 구축해야 하는 팀에게 AutoML은 완벽한 솔루션입니다. 라벨이 지정된 데이터세트를 제공하기만 하면 Vertex AI의 알고리즘이 자동으로 특성 공학, 모델 선택 및 하이퍼파라미터 튜닝을 처리하여 최적화된 모델을 제공합니다.
*   **맞춤 학습:** 완전한 제어가 필요한 데이터 과학자를 위해 맞춤 학습 작업을 사용하면 TensorFlow, PyTorch 또는 Scikit-learn과 같은 인기 있는 프레임워크를 사용하여 자체 학습 코드를 실행할 수 있습니다. 코드를 컨테이너에 패키징하여 Vertex AI의 확장 가능한 학습 서비스에 제출하면 모델 아키텍처 및 학습 로직에 대한 완전한 유연성을 확보할 수 있습니다.
*   **BigQuery ML:** 데이터 분석가와 SQL에 능숙한 사용자를 위해 BigQuery ML은 독특한 경로를 제공합니다. 이를 통해 표준 SQL 쿼리를 사용하여 BigQuery 내에서 직접 머신러닝 모델을 생성하고 실행할 수 있으므로 데이터가 있는 곳으로 직접 ML 기능을 가져올 수 있습니다.

### 사전 학습된 API 활용: Cloud Vision, Natural Language 등

모든 사용 사례에 처음부터 모델을 구축해야 하는 것은 아닙니다. 일반적인 AI 작업을 위해 Google Cloud는 간단한 API 호출만으로 정교한 AI 기능을 애플리케이션에 통합할 수 있는 강력한 사전 학습된 API를 제공합니다.

*   **Cloud Vision API:** 이 API를 사용하면 애플리케이션이 이미지의 내용을 이해할 수 있습니다. 객체와 얼굴을 감지하고, 인쇄된 텍스트와 손글씨를 읽고, 이미지 카탈로그화를 위한 귀중한 메타데이터를 생성할 수 있습니다.
*   **Cloud Natural Language API:** 이 API를 사용하여 텍스트를 분석하고 이해할 수 있습니다. 감성 분석 수행, 주요 개체(예: 사람, 장소, 이벤트) 식별, 문법 구조 분석 등의 기능이 포함됩니다.

음성-텍스트 변환, 번역, 동영상 인텔리전스를 위한 다른 API와 함께 이러한 API는 전체 ML 수명 주기의 오버헤드 없이 애플리케이션에 인텔리전스를 추가할 수 있는 강력한 지름길을 제공합니다.

## 파트 4: 배포 및 운영 - GCP에서의 MLOps

머신러닝 모델이 학습되고 평가된 후에도 여정은 끝나지 않았습니다. 모델의 진정한 가치는 비즈니스 성과를 이끌어내는 예측을 제공하며 프로덕션 환경에 배포될 때 실현됩니다. 바로 이 지점에서 머신러닝 운영(MLOps)이 중요해집니다. MLOps는 DevOps 원칙을 머신러닝 수명 주기에 적용하여 자동화, 재현성, 지속적인 모니터링에 중점을 둡니다. 데이터 중심 플랫폼이라는 Google Cloud의 핵심 정체성은 전체 ML 수명 주기 관리를 위한 통합 플랫폼인 Vertex AI를 중심으로 한 포괄적인 MLOps 도구에서 잘 드러납니다(Google Cloud, n.d.).

### Vertex AI Pipelines: ML 워크플로 자동화
견고한 MLOps 관행의 기반은 자동화입니다. 데이터 준비, 학습, 평가, 배포 단계를 수동으로 반복하는 것은 비효율적이고 오류가 발생하기 쉽습니다. Vertex AI Pipelines는 ML 워크플로를 일련의 오케스트레이션된 단계로 자동화하는 프레임워크를 제공합니다. 파이프라인을 정의함으로써, 일정에 따라 또는 Cloud Storage 버킷에 새 데이터가 도착하는 것과 같은 이벤트에 의해 트리거될 수 있는 반복 가능하고 서버리스인 프로세스를 생성할 수 있습니다. 이는 일관성을 보장하고 팀이 더 빠르고 안정적으로 모델을 빌드, 테스트 및 배포할 수 있도록 합니다(Google Cloud, n.d.).

### 모델 배포: 실시간 예측을 위한 엔드포인트 생성
사기 탐지나 실시간 제품 추천과 같이 즉각적인 피드백이 필요한 애플리케이션의 경우, 모델은 실시간 예측을 위해 사용 가능해야 합니다. Vertex AI는 이 과정을 상당히 단순화합니다. 학습 후, Vertex AI 모델 레지스트리에 모델을 등록하고 몇 번의 클릭이나 API 호출만으로 전용 엔드포인트에 배포할 수 있습니다. 이를 통해 애플리케이션이 낮은 지연 시간의 예측을 받기 위해 호출할 수 있는 확장 가능하고 안전한 REST API가 생성됩니다. GCP는 기본 인프라를 관리하며, 변동하는 요청량을 처리하기 위해 자동으로 확장하므로, 사용자는 서버 관리보다는 애플리케이션 로직에 집중할 수 있습니다.

### 대규모 추론을 위한 배치 예측
모든 사용 사례에 실시간 추론이 필요한 것은 아닙니다. 고객 데이터베이스를 세분화하거나 주간 보고서를 위해 대규모 데이터 세트를 스코어링하는 등의 작업에는 배치 예측이 더 효율적이고 비용 효과적인 접근 방식입니다. Vertex AI는 테라바이트 규모의 데이터를 처리할 수 있는 배치 예측 작업을 지원합니다. 배치 작업을 BigQuery나 Cloud Storage에 있는 입력 데이터를 가리키도록 설정하면, Vertex AI는 전체 데이터 세트에 대해 모델을 실행하는 데 필요한 리소스를 프로비저닝하고 출력 예측을 원하는 목적지에 저장합니다. 이는 지속적으로 실행되는 엔드포인트의 오버헤드 없이 GCP의 강력한 데이터 처리 능력을 활용하여 방대한 데이터 세트에 ML 통찰력을 적용하는 것입니다.

### 모델 모니터링: 드리프트 및 스큐 감지
모델이 보는 프로덕션 데이터가 학습에 사용된 데이터와 달라지기 시작하면 시간이 지남에 따라 모델의 성능이 저하될 수 있습니다. 이 현상을 "드리프트(drift)"라고 합니다. Vertex AI 모델 모니터링은 이러한 성능 저하를 감지하고 사용자에게 알리는 중요한 서비스입니다. 이 서비스는 들어오는 예측 요청을 자동으로 분석하고 그 통계적 속성을 학습 데이터 기준선과 비교합니다. 이 서비스는 **학습-서빙 스큐**(학습 데이터와 프로덕션 데이터 분포 간의 불일치)와 **특성 드리프트**(시간에 따른 프로덕션 데이터 분포의 변화)를 모두 감지할 수 있습니다. 심각한 드리프트에 대한 알림을 설정함으로써, 모델의 성능이 위험에 처했을 때 사전에 알림을 받아 최신 데이터로 모델을 재학습해야 할 시점임을 알 수 있습니다(Google Cloud, n.d.).

### 서버리스 ML: Cloud Functions로 예측 트리거하기
GCP의 강점은 서비스들의 원활한 통합에 있습니다. Cloud Functions와 같은 서버리스 도구를 사용하여 강력한 이벤트 기반 ML 애플리케이션을 만들 수 있습니다. Cloud Function은 사용자가 서버를 프로비저닝하거나 관리할 필요 없이 이벤트에 응답하여 실행되는 코드 조각입니다. 예를 들어, 새 이미지가 Cloud Storage 버킷에 업로드될 때마다 트리거되도록 Cloud Function을 구성할 수 있습니다. 이 함수는 배포된 Vertex AI 모델 엔드포인트를 호출하여 예측(예: 이미지 내용 분류)을 얻고, 그 결과를 BigQuery 테이블이나 Firestore 데이터베이스에 저장할 수 있습니다. 이러한 서버리스, 이벤트 기반 아키텍처는 확장 가능하고 비용 효율적이며 반응성이 뛰어난 ML 기반 기능을 구축하는 데 완벽합니다(Google Cloud, n.d.).

## 파트 5: 모든 것을 하나로 묶기 - 엔드투엔드 ML 워크플로우 예시

이론도 중요하지만, Google Cloud Platform의 구성 요소들이 어떻게 연결되어 실제 문제를 해결하는지 직접 보는 것에서 진정한 이해가 시작됩니다. 이 섹션에서는 데이터 과학자가 GCP의 데이터 중심 서비스를 활용하여 원시 데이터에서부터 완전히 배포되고 자동화된 AI 솔루션에 이르기까지의 과정을 보여주는 일반적인 엔드투엔드 머신러닝 워크플로우를 단계별로 살펴봅니다.

### 1단계: Cloud Storage 버킷으로 원시 데이터 수집

모든 머신러닝 프로젝트는 데이터에서 시작됩니다. 첫 번째 단계는 구조화된 데이터(CSV, 로그), 반구조화된 데이터(JSON), 비구조화된 데이터(이미지, 문서) 등 형태에 관계없이 원시 데이터를 위한 중앙 집중적이고 확장 가능하며 내구성 있는 위치를 마련하는 것입니다.

**Google Cloud Storage**는 이 작업에 가장 이상적인 서비스입니다. 이것은 어떤 양의 데이터든 저장할 수 있도록 설계된 확장성이 뛰어나고 복원력이 강한 객체 스토리지 서비스입니다. 컨테이너 역할을 하는 "버킷"을 생성하고 원시 데이터 세트를 업로드할 수 있습니다. 이 버킷은 프로젝트 초기 데이터의 단일 진실 공급원(single source of truth)이 되며, 다른 GCP 서비스에서 후속 처리를 위해 접근할 수 있습니다.

### 2단계: BigQuery를 사용한 데이터 정제 및 변환

원시 데이터는 모델 학습에 바로 사용될 수 있는 경우가 거의 없습니다. 데이터를 정제하고, 전처리하며, 특성(feature)으로 변환해야 합니다. 이를 위해 Cloud Storage의 랜딩 존(landing zone)에 있는 데이터를 강력한 분석 엔진으로 옮깁니다.

Google의 서버리스 데이터 웨어하우스인 **BigQuery**는 이 단계의 핵심입니다. Cloud Storage의 데이터를 BigQuery 테이블로 쉽게 로드할 수 있습니다. 데이터 과학자는 표준 SQL을 사용하여 페타바이트 규모에서 복잡한 변환을 수행하고, 결측값을 처리하며, 여러 데이터 세트를 조인하고, 특성을 엔지니어링할 수 있습니다. 머신러닝을 시작하려는 데이터 분석가를 위해, **BigQuery ML**은 익숙한 SQL 명령을 사용하여 데이터 웨어하우스 내에서 직접 모델을 구축하고 실행할 수 있게 해주어 복잡성의 상당 부분을 추상화합니다. 이 단계의 결과물은 학습 준비가 완료된 깨끗하고 선별된 데이터 세트입니다.

### 3단계: Vertex AI Training을 사용한 커스텀 모델 학습

BigQuery에 준비된 데이터 세트가 있으면 다음 단계는 머신러닝 모델을 학습시키는 것입니다. BigQuery ML이 특정 사용 사례에 탁월하지만, 복잡한 모델은 종종 전용 ML 플랫폼의 성능과 유연성을 필요로 합니다.

**Vertex AI**는 모든 ML 관련 작업을 위한 Google의 통합 플랫폼입니다. Vertex AI Training을 사용하면 TensorFlow, PyTorch 또는 Scikit-learn과 같은 인기 있는 프레임워크를 사용하여 커스텀 학습 작업을 실행할 수 있습니다. 학습 코드를 컨테이너에 패키징하고, 필요한 머신 유형(강력한 GPU 포함)을 지정하며, BigQuery 또는 Cloud Storage에 있는 학습 데이터를 가리키도록 할 수 있습니다. Vertex AI는 인프라 프로비저닝 및 실행을 처리하므로, 사용자는 최상의 모델을 구축하는 데만 집중할 수 있습니다.

### 4단계: Vertex AI 엔드포인트에 모델 배포

학습된 모델은 새로운 데이터에 대한 예측을 수행할 수 있을 때만 유용합니다. 모델을 애플리케이션에서 사용할 수 있도록 만드는 과정을 배포라고 합니다.

Vertex AI는 이 과정을 크게 단순화합니다. 학습 작업이 완료되면 결과물인 모델 아티팩트가 저장됩니다. 그런 다음 이 아티팩트를 Vertex AI 모델 레지스트리에 등록하고, 몇 번의 클릭이나 간단한 API 호출만으로 **Vertex AI 엔드포인트**에 배포할 수 있습니다. 이를 통해 안전하고 확장 가능하며 완전 관리형인 HTTP 엔드포인트가 생성됩니다. 이제 애플리케이션은 이 엔드포인트의 API로 새로운 데이터를 보내고 모델로부터 실시간 예측을 받을 수 있습니다.

### 5단계: Vertex AI Pipelines로 파이프라인 자동화

이러한 단계를 수동으로 실행하는 것은 일회성 프로젝트에서는 가능하지만, 확장 가능하거나 재현 가능하지는 않습니다. 프로덕션 수준의 ML을 위한 마지막이자 가장 중요한 단계는 전체 워크플로우를 자동화하는 것입니다.

**Vertex AI Pipelines**는 모든 것을 하나로 묶는 오케스트레이션 서비스입니다. 이를 통해 BigQuery에서의 데이터 수집 및 전처리부터 Vertex AI에서의 모델 학습 및 배포에 이르는 전체 워크플로우를 방향성 비순환 그래프(DAG)로 정의할 수 있습니다. 각 단계는 파이프라인의 구성 요소가 됩니다. 이 자동화된 파이프라인은 주기적으로 실행되도록 예약하거나 이벤트(예: Cloud Storage 버킷에 새 데이터가 도착하는 것)에 의해 트리거될 수 있습니다. 이러한 MLOps 관행은 최소한의 수동 개입으로 모델을 일관되고 안정적으로 재학습하고 재배포할 수 있도록 보장합니다.

## 시작하기: Google Cloud에서 첫 AI 프로젝트 시작하기

Google Cloud Platform(GCP)은 기본적으로 데이터 중심 플랫폼으로, 핵심 강점은 빅데이터, 분석, AI/ML 서비스에 집중되어 있습니다(Google Cloud Platform 서비스 카탈로그). 이로 인해 GCP는 탐색 단계에서 프로덕션 단계까지 작업을 확장하려는 데이터 과학자에게 자연스러운 환경이 됩니다. 이 섹션에서는 첫 프로젝트를 시작하고, 전문가 수준의 개발 환경을 설정하며, 방대한 공개 데이터세트에 대해 첫 쿼리를 실행하는 실습 가이드를 제공합니다. 이 모든 과정을 단 몇 분 안에 완료할 수 있습니다.

프로젝트가 생성되면 데이터 과학 작업을 위한 샌드박스 환경이 준비됩니다(Google Cloud 문서).

노트북을 시작하려면:
1.  Cloud 콘솔의 탐색 메뉴를 사용하여 **Vertex AI -> Workbench**로 이동합니다.
2.  **'관리형 노트북'** 탭을 선택하고 **'+ 새 노트북'**을 클릭합니다.

5.  **'만들기'**를 클릭합니다. 몇 분 후 인스턴스가 준비됩니다. **'JupyterLab 열기'**를 클릭하여 환경을 시작합니다.

### 탐색을 위해 공개 BigQuery 데이터세트에 연결하기

이제 흥미로운 부분인 데이터 액세스 및 분석 단계입니다. Vertex AI 노트북을 Google의 서버리스, 페타바이트급 데이터 웨어하우스인 **BigQuery**에 연결합니다. 사용 가능한 여러 공개 데이터세트 중 하나를 사용하여 간단한 쿼리를 수행할 것입니다.

JupyterLab 환경 내의 새 노트북 파일에서 다음 Python 코드를 실행하세요:

```python
# BigQuery 클라이언트 라이브러리 가져오기
from google.cloud import bigquery

# "Client" 객체 생성
# 노트북 환경의 사용자 인증 정보를 자동으로 사용합니다
client = bigquery.Client()

# 공개 데이터세트에 대한 SQL 쿼리 정의
# 이 쿼리는 2010년 미국에서 가장 인기 있는 아기 이름을 찾습니다
sql_query = """
    SELECT
        name,
        SUM(number) as total_count
    FROM
        `bigquery-public-data.usa_names.usa_1910_current`
    WHERE
        year = 2010
    GROUP BY
        name
    ORDER BY
        total_count DESC
    LIMIT 10
"""

# 쿼리를 실행하고 결과를 pandas DataFrame으로 로드합니다
df = client.query(sql_query).to_dataframe()

# 결과를 표시합니다
print("2010년 미국 인기 아기 이름 Top 10:")
print(df.head(10))
```

이 셀을 실행하면 BigQuery 클라이언트 라이브러리가 원활하게 인증하고 방대한 `usa_names` 데이터세트에 대해 SQL 쿼리를 실행합니다. 결과는 익숙한 pandas DataFrame으로 직접 반환되어 추가 분석 및 시각화를 위해 준비됩니다. 이로써 개발 환경과 강력한 빅데이터 도구를 성공적으로 연결했으며, 이는 GCP를 사용하는 모든 데이터 과학자를 위한 기본 워크플로우입니다(BigQuery 및 BigQuery ML용 공식 Google Cloud 문서).
